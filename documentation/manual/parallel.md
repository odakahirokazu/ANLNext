# 6. 並列実行

[目次](README.md) · [前：Submodule](submodules.md) · [次：ステータス・移行](reference.md)

## チェーンを複製して処理する

`ANLManagerMT(n)`またはChainの`num_parallels = n`で、合計`n`本のチェーンを使います。
チェーンの先頭から末尾までが一つの反復を処理し、反復を各ワーカーに分担させます。
個々のモジュールを独立した処理段階のスレッドに分ける方式ではありません。

元チェーンの`mod_pre_initialize()`を終えた後に複製し、
複製先も含めて`mod_initialize()`を実行します。
全チェーンへ配るパラメータとSubmodule実体は、複製前に設定します。

## モジュールのコピー設計

正規モジュールでは`ENABLE_PARALLEL_RUN()`が複製処理を有効にします。
フレームワークはコピーコンストラクタを使い、パラメータ参照先と登録済みSubmoduleを結び直します。
`ParameterRegistry`自体を通常の値としてコピーする方式ではありません。

| メンバの種類 | 設計時に確認すること |
| --- | --- |
| 数値・文字列・値のコンテナ | 通常は各コピーが独立した値を持つ |
| 通常のポインタ | コピー元と同じ実体を指す。意図した共有か確認 |
| `shared_ptr` | 実体を共有する。変更時の同期が必要か確認 |
| `unique_ptr`などコピー不能な資源 | コピーコンストラクタを実装するか、複製後に確保 |
| 接続を宣言したSubmoduleポインタ | フレームワークが対応する複製実体へ接続 |

コピーコンストラクタは、必要がなければ暗黙生成や`= default`を使用できます。
独自実装では基底の`BasicModule`のコピーコンストラクタを呼び、
各ユーザーメンバの所有権と初期状態を決めてください。
単にコンパイルを通すために、独立すべき資源を共有する設計にはしないでください。

## copy_idとチェーンごとの設定

元モジュールの`copy_id()`は`0`、フレームワークが順に複製したものは`1`以降です。
`copy_id`はモジュールの複製番号で、通常の並行チェーン構築ではチェーン番号に対応します。
`is_master()`で元モジュールか確認できます。

スクリプトの`modify`は複製後・初期化前に呼び出されます。
`get_parallel_module(chain_id, module_id)`で各実体にアクセスできます。
元チェーンへの設定を複製後に変えても、ほかのチェーンへ自動伝播するものではありません。
チェーンごとに変更する場合は対象を明示し、直接setterを使うか、設定予約の適用先に注意してください。
この段階でSubmoduleの構成を変更する運用はしません。

## 順序が必要な処理

入力の読み出しや外部装置への書き込みなど、反復番号順に処理したいモジュールでは、
複製前に`set_order_sensitive(true)`を設定します。
たとえば、そのモジュールのコンストラクタで呼び出せます。

フレームワークのOrderKeeperが、該当モジュールの`mod_analyze()`をloop番号順に通します。
ほかのモジュールは並列に処理できます。
順序保証の範囲はそのモジュールの処理であり、任意の共有メモリ全体を保護するロックではありません。

SKIPや無効なモジュールでも順序制御点を通過し、後の反復を待ち残しません。
通常のQUITでは順序制御を継続して終了します。
例外やcriticalステータスではcancelを通知し、待機中の処理を解放します。
実行中のユーザー処理を強制停止したり、完了済みの副作用を巻き戻したりはしません。
通常、ユーザーがOrderKeeperやKeeperBlockを直接操作する必要はありません。

## 結果の集約

解析結果の集約は、フレームワークの統計集約と分けて考えます。
モジュールの結果は、元チェーンの`mod_reduce()`で集約します。

```cpp
anlnext::ANLStatus mod_reduce(
    const std::vector<anlnext::BasicModule*>& parallel_modules) override;
```

引数は、元モジュール自身を除く、同じ位置の複製モジュールをチェーン順に並べたものです。
デフォルト実装は各要素に対して`mod_merge(const BasicModule*)`を呼びます。
加算による集約なら、[第4章の例](module_development.md)のように`mod_merge()`だけを実装できます。
非正常ステータスを返せば集約を中断し、マネージャーはその結果を返します。

フレームワークは処理回数・エラーカウント・Evsを別に集約します。
`define_result()`しただけで、任意のユーザーデータの集約方法が決まるわけではありません。
複数回runでは、その都度の結果を集約するのか累積結果を保持するのかを定め、
`mod_begin_run()`・`mod_end_run()`・`mod_reduce()`／`mod_merge()`の役割を揃えてください。

## チェーンの一つだけで動かすモジュール

`set_singleton(copy_id)`を設定すると、指定したコピーだけが有効になり、ほかはoffになります。
ここでのsingletonは、全チェーンから一つのオブジェクトを共有する指定ではありません。
複製後の有効・無効の切り替えです。
共有先への参照が必要な場合は、それも含めてモジュール側で設計してください。
